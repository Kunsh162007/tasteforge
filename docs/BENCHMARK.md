# Fabrication benchmark

How often does a plain LLM name venues, artists and brands that Qloo cannot confirm, and how does TasteForge compare? Generated by `npm run benchmark` on 2026-10-20; 20 of 20 prompts completed.

## Headline

- **Places a plain LLM named that Qloo could not confirm in the requested city:** 56% (38 not found, 26 in another city, of 115). TasteForge: 0% of 120.
- **Picks Qloo could not find at all (all types):** baseline 29%, TasteForge 0%.
- **Share of place picks that are verified and local:** baseline 44%, TasteForge 100%.
- **Repeat-run consistency** (3 prompts, 2 runs each): picks overlap 87% for the plain LLM and 80% for TasteForge.

## Results (20 prompts, 5 cities: Indore, London, Brooklyn, Chicago, Paris)

Baseline = the Taste Proof baseline: a plain LLM with no Qloo data, asked for artists, places and brands for the same prompt. TasteForge = the picks in TasteForge's brief. Each pick is checked against Qloo.

| Pick type | Picks (baseline / TasteForge) | Not found: baseline | Not found: TasteForge | Off-city: baseline | Off-city: TasteForge | Mean fit: baseline | Mean fit: TasteForge |
|---|---|---|---|---|---|---|---|
| Artists | 111 / 120 | 31% (34) | 0% (0) | n/a | n/a | 0.90 | 0.89 |
| Places | 115 / 120 | 33% (38) | 0% (0) | 34% (26/77) | 0% (0/120) | 0.78 | 0.79 |
| Brands | 80 / 80 | 20% (16) | 0% (0) | n/a | n/a | 0.82 | 0.86 |

- **Not found**: no Qloo entity of that type has a matching name among the top 5 search hits. Fuzzy hits with a different name do not count, so the baseline gets the benefit of the doubt.
- **Off-city** (places only): the matching entity closest to the city centre lies more than 50 km from it. Counted among found places that have coordinates.
- **Mean fit**: Qloo's affinity for the picks it found, scored against the audience's taste signals with `filter.results.entities`. Picks that were not found are left out, never averaged in as zero.
- Mean fit covers 190 baseline and 302 TasteForge picks; the others were not found, or Qloo's scoring request timed out.

## Repeat-run consistency

Three prompts, each run twice with the real synthesis step (2026-10-21, live Qloo, the fast model chain for every call). Overlap is the Jaccard overlap of pick names (1 = identical lists). Every pick is a real Qloo result; what can still change between two runs is Qloo's own answers, which questions the model asks, and which of the ranked results the writer takes.

What changed in the pipeline: the model runs at temperature 0 (the writer used 0.3); seed plans are cached per normalized prompt; the seed reply is read leniently (one reply with `"kind": "film"` used to fail the whole plan, which made the run fall back to searching the request text and produced the 0-pick briefs); Qloo results are sorted by affinity, then id; the writer is told to take entities in ranked order; and a section left under its floor (4 places, 5 artists, 3 brands) after synthesis gets one repair call, then is filled from the ledger.

Two configurations were measured. **After** is the app's own (seed cache on, so the second run reuses the first run's seeds): the numbers in the table. With the seed cache off (the model alone at temperature 0, 35 calls in all) the overlaps were 86% (indore-cafe), 100% (london-studio) and 73% (brooklyn-shop), mean 86%. Both are far above 17%, but not 100%: a different seed plan or writer choice still moves a few picks, and Qloo itself is not guaranteed to answer identically. Three prompts and two runs each: indicative only. The plain-LLM baseline is a free-running call and is not meant to be repeatable; its 100% for two prompts at temperature 0 says the model answers the same way, not that it is correct.

## Method

- **Prompts:** 20 prompts across 5 cities, mixing cafes, shops, studios and events, in both modes (listed below). Cities were chosen from `npm run qloo:check`, which shows live place, decor/ambience and heatmap coverage for each.
- **Baseline:** one LLM call asking for about 6 artists, 6 places and 4 brands with no Qloo data (the same call the app's Taste Proof makes). Names the user typed into the prompt are removed from both lists, as in the app.
- **TasteForge:** the full hybrid pipeline against live Qloo. In the 20-prompt set the synthesis step is replaced by a deterministic writer, so TasteForge's picks are the Qloo entities the walk returned, in order, capped at the same counts as the baseline. This keeps the free LLM quota usable; the six consistency runs use the real synthesis. The real brief can only cite entities from this same evidence, so its not-found and off-city rates are the same by construction; its picks and their fit can differ.
- **Models (fast chain, all calls):** groq:openai/gpt-oss-120b, groq:qwen/qwen3.8-27b, groq:openai/gpt-oss-20b, gemini:gemini-3.5-flash-lite, gemini:gemini-2.5-flash. Real LLM calls used: 118.
- **Scoring:** one `/v2/insights` call per pick type with `filter.results.entities`, using the same audience signals for both lists.

## Caveats

- Qloo's catalogue is not the world. A real venue missing from Qloo counts as "not found", so the not-found rate overstates fabrication; it is better read as "cannot be verified or located by Qloo". Indore has far thinner coverage than London or Chicago, and its place results are the most likely to be missing.
- TasteForge returns only what Qloo returned, so its not-found and off-city rates are about 0% by design. That is the point of the architecture, not a measured model skill.
- Affinity measures fit with the audience's taste signals, not quality. A plain LLM that names famous places can still score well on fit. The fit gap is small and varies by prompt; the fabrication gap is the stronger claim.
- A fuzzy name match can be generous: a short chain name can match a branch in another city. We take the closest match, which favours the baseline.
- The baseline model matters. Here the baseline is the fast chain (mostly Groq gpt-oss-120b, which knows fewer local venues than the large Gemini models). Four full runs of the same 20 prompts on 2026-10-20 (different model mixes and small changes to name matching while we built the benchmark) gave 43%, 59%, 47% and 56% of baseline places unverified; read the headline as roughly half, not as a precise rate. TasteForge's 0% does not depend on the baseline model.
- One run of each prompt, 20 prompts, one day: treat percentages as indicative, not as confidence intervals.
- The LLM free tiers change quickly; model names above are what answered on the day.

```bash
# needs QLOO_MODE=live, QLOO_API_KEY and GROQ_API_KEY and/or GEMINI_API_KEY in .env.local
npm run benchmark -- --write
```
